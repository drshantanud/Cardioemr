# CardioEMR

Multicentre cardiology EMR and research registry (heart failure, lipid and CAD registries).

| Path | What it is |
|---|---|
| `db/migrations/` | PostgreSQL 16 schema, applied in order (`0001_init.sql` onward). Row-level security isolates centres; audit is append-only and hash-chained. |
| `db/tests/` | SQL acceptance tests for the migrations (`test_results.txt` holds the last run). |
| `db/dictionaries/` | HF, lipid and CAD data dictionaries as CSV, generated by `tools/generate_dictionaries.py`. |
| `api/registry-api-v0.1.yaml` | Registry API contract (OpenAPI 3.1). |
| `backend/` | FastAPI implementation of the contract. |
| `web/` | Web app (Next.js): sign-in, centre and role choice, patients, consultations and prescribing. See `web/README.md`. |

## Backend

```bash
cd backend
pip install -r requirements-dev.txt
# tests build a fresh database from db/migrations on a PostgreSQL 16 server
CEMR_TEST_ADMIN_URL=postgresql://postgres:postgres@localhost:5432/postgres python -m pytest
```

Running the API needs:

| Variable | Meaning |
|---|---|
| `CEMR_DATABASE_URL` | Connection as the `cardioemr_api` login role (never a superuser or table owner) |
| `CEMR_OIDC_ISSUER`, `CEMR_OIDC_AUDIENCE`, `CEMR_OIDC_JWKS_URL` | Identity provider that signs access tokens |

```bash
uvicorn app.main:create_app --factory
```

Every request carries `Authorization: Bearer <token>`, `X-Centre-Id` and `X-Acting-Role`. The API opens one
transaction per request, switches to the database role for the acting role, and row-level security does the rest.

### What is implemented

| Area | Endpoints |
|---|---|
| Session and patients | `GET /me` (centres and roles, no centre headers), `GET/POST /patients`, `GET/PATCH /patients/{id}` |
| Consultations | `GET/POST /patients/{id}/encounters`, `GET/PUT /encounters/{id}` (draft), `POST /encounters/{id}/sign`, `POST /encounters/{id}/amendments`, `GET/POST /patients/{id}/vitals`, `GET/POST /patients/{id}/diagnoses`, `PATCH /diagnoses/{id}`, `POST /patients/{id}/allergies`, `PATCH /allergies/{id}`, `GET /concepts`, `GET /patients/{id}/clinical-summary` |
| Medicines | `GET /drugs`, `GET/POST /patients/{id}/medications`, `GET /medication-courses/{id}`, `POST /medication-courses/{id}/events`, `POST /medication-events/{id}/void` |
| Protocols and dictionaries | `/registries`, `/protocols/{id}`, `/protocols/{id}/data-dictionary` |
| Suggestions and enrolment | `/registry-suggestions`, `/enrolments` (screening, eligibility, enrol, status, schedule) |
| Assessments | open, read, save values, verify, complete, lock and unlock; `POST /assessments/{id}/prefill` |
| Heart failure | `GET/PUT /assessments/{id}/hf/gdmt` |
| Lipid | `GET/PUT /assessments/{id}/lipid/targets` (ESC/EAS 2019 primary, LAI 2020 secondary) |
| CAD | `/patients/{id}/pci-procedures`, `/pci-procedures/{id}` with lesions and stents |
| Events | `POST /events`, `GET/PUT /events/{id}`, `GET /patients/{id}/events`, `PUT /events/{id}/adjudications/{id}`, `GET /protocols/{id}/adjudication-queue` |
| Reports | `GET /protocols/{id}/follow-up-due`, `GET /protocols/{id}/missing-data` |
| Exports | `POST/GET /exports`, `GET /exports/{id}`, `POST /exports/{id}/decision`, `GET /exports/{id}/file` |

Prefill (`backend/app/prefill.py`) fills `emr_derived` and `calculated` variables from the chart, using the
variable's `derivation_key`. It never overwrites a stored value, records the source row, and leaves every
value unverified. Rules not written yet (angiography, devices, adherence, target lesion and vessel
revascularisation, and a few others) are reported as `not_automated_yet`.

### Consultations and prescribing (migration 0008)

A consultation is a draft until a clinician signs it; nurses can help write the draft. Saving replaces the
complaint list and the structured assessment, and refuses a stale version (412). A signed note is frozen in
the database: fields are changed only by an amendment with a reason, and the earlier text is kept.

A medicine is a course with an append-only list of events (start, dose change, hold, resume, stop, continue).
The API works out the daily dose in the drug's reference unit (strength × quantity × doses per day) and
classifies a dose change as an increase, decrease, frequency change or product change. A wrong entry is
voided, never deleted. Prescribing is refused when the drug is already active (`ALREADY_PRESCRIBED`) or an
active allergy names the drug, its ingredient or one of its classes (`ALLERGY`); a beta-blocker class allergy
also covers atenolol and propranolol. Migration 0008 adds 25 commonly co-prescribed drugs in classes of their
own so they do not count towards the GDMT pillars; **the catalogue additions need clinical review.**

### Events and adjudication (migration 0006)

An event is reported once. The database opens a pending adjudication for every protocol the patient is
enrolled in at that centre whose component endpoints use the event type and need adjudication. Decisions are
human: a clinician or PI who did not report the event, with a classification from the endpoint's
classification system (`ref.adjudication_classifications`). Changing a decision needs a change reason;
changing the facts of an adjudicated event sends it back to pending; entering the event in error withdraws its
adjudications. `registry.v_endpoint_events` and `research.v_time_to_first_event` count only confirmed events.
Every endpoint definition stays `draft` until the clinical lead signs it off.

### Unit conversion

A numeric value may be saved in any unit listed in the variable's `accepted_units` (data dictionary). The
database converts it to the variable's unit (lab factors from `ref.unit_conversions`, physical units from
`ref.quantity_units`), range-checks the converted value, and keeps the typed value and unit.

### Research exports

Requested by a research coordinator or PI with export rights, approved by a different PI. After the decision
commits the export runs as the requester, with their own study access, from the pseudonymised research views
only: subject codes, days from index, ages above 89 written as 90, date variables as days or years.
`aggregate_only` writes counts and summaries with cells under 5 shown as `<5`. Files are zips of CSV tables
(csv, r_csv, stata_csv, spss_csv with a labels.sps) or one xlsx, with the data dictionary and a manifest.

| Variable | Meaning |
|---|---|
| `CEMR_EXPORT_DIR` | Where finished export files are kept (required for exports) |
| `CEMR_EXPORT_URL_KEY` | Key that signs 15-minute download links (random per start-up if unset) |
| `CEMR_EXPORT_RETENTION_DAYS` | Days a finished export can be downloaded (default 7) |
